本文件演示技能的完整调用方式：用户怎么说、AI 按执行流程做什么、每步产出什么。AI 在需要示范或对流程有疑问时按需加载本文件。

## 示例 1：最小调用 — React 待办应用

### 用户输入

> 帮我把 D:\projects\todo-app 这个代码库变成课程，我想搞懂我让 AI 改代码的时候它到底在改哪里。

### AI 执行过程（对应 SKILL.md 执行流程分步）

**第 0 步 · 选档（必问，等待确认）**：AI 先回复"用哪个档位：① 快览档（约 4 屏看大局）② 标准档 ③ 精讲档？"，用户确认"标准档"后才进入第 1 步（完整对话示范见示例 8）。

**第 1 步 · 物理拓扑与入口点映射**

```
todo-app/
├── package.json          → React 18 + Vite
├── index.html
├── src/
│   ├── main.jsx          → 入口：ReactDOM.createRoot 挂载 <App/>
│   ├── App.jsx           → 顶层组件，持有 todos 状态
│   ├── components/
│   │   ├── TodoInput.jsx  → 输入框 + 添加按钮
│   │   ├── TodoList.jsx   → 列表渲染
│   │   └── TodoItem.jsx   → 单条待办（勾选/删除）
│   └── hooks/
│       └── useLocalStorage.js  → 状态持久化到 localStorage
```

- **入口拓扑**：仅一种启动方式——浏览器加载 index.html → 构建入口 main.jsx → `createRoot(...).render(<App/>)`，验证闭环
- **依赖分层**：react / react-dom 为**运行时强依赖**；无外部服务 SDK，持久化用浏览器原生 localStorage（**可替换抽象层**为零）——课程要明确告诉学习者"这个应用没有后端"这一事实

**第 2 步 · 确定 3 个用户操作流程**

1. 添加一条待办（最高频）
2. 勾选完成 / 取消完成
3. 刷新页面后待办还在（持久化）

**第 2.5 步 · 建四张表**：建隐喻分配表（含「映射到的代码实体」列）、术语定义表、测验溯源对照表与**变量词典**（v1.18.0 起升为交付物，进课程正文的 `.vardict-scene`，见第 5 步展示的隐喻表），全程查重维护；第 7 步出题时逐题登记溯源表。

**第 3 步 · 架构级深读（以流程 1"添加待办"为例，按 3a–3d 展开）**

- **3a 事件链**：输入框回车 → `TodoInput.jsx` 的 `handleSubmit()` → 经 props 上抛 `onAdd(text)` → `App.jsx` 的 `addTodo()` 执行 `setTodos([...todos, newTodo])` → React 重渲染 `<TodoList/>` → `.map()` 出每条 `<TodoItem/>` → `useLocalStorage` 副作用写盘。全程同步、无队列无重试——这本身就是一个值得告诉学习者的事实
- **3b 数据变形**：`"买牛奶"`（输入字符串）→ `{id: Date.now(), text, done:false}`（对象）→ `[...todos, newTodo]`（新数组，不可变更新）→ JSON 字符串（localStorage 只能存字符串）。变形人分别是 `addTodo` 与 `JSON.stringify`
- **3c 错误边界**：路径上无 try-catch。**静默失败点**：隐私模式 / 存储写满时 `localStorage.setItem` 抛错但副作用未捕获 → 测验素材："Safari 隐私模式下待办全丢，先查哪里？"
- **3d 配置与扩展**：无 env 配置。扩展面：加"星标"要动 `App.jsx`（状态形状）+ `TodoItem.jsx`（显示），`useLocalStorage` 是通用层不用动 → 结业测验答案来源

**第 4 步 · 逐字提取代码片段**（示例）

从 `src/App.jsx` 第 12–18 行原样复制：

```jsx
  const addTodo = (text) => {
    const newTodo = { id: Date.now(), text, done: false };
    setTodos([...todos, newTodo]);
  };
```

⚠️ 注意缩进、空行、`Date.now()` 一律保留，不美化不改写。

**第 5 步 · 写大白话翻译**（每段 1–2 句）

| 代码段 | 大白话 |
|---|---|
| `const newTodo = {...}` | 造一张新便签：写上内容、盖个时间戳当编号、默认没打勾。 |
| `setTodos([...todos, newTodo])` | 把旧便签全部抄一遍，再把新的贴最后——React 不许直接改原数组，只许换一本新的。 |
| `useLocalStorage` 副作用 | 每次便签本变样，就复印一份塞进浏览器的抽屉里，刷新也不丢。 |

隐喻分配表（第 2.5 步建立，写作时查重）：
- React 状态 → 便签本（仅此一次）
- localStorage → 浏览器的抽屉（仅此一次）
- `.map()` 渲染 → 流水线盖章（仅此一次）

**第 6 步 · 按需加载 references**

只读 `interactive-elements.md` §8 速查表，决定：
- 流程 1（添加待办）→ §3 探照灯：App.jsx / TodoInput.jsx / useLocalStorage.js 三文件的调用行跨文件同步点亮（站点带 data-sp-pair/data-sp-line）
- 流程 3（持久化）→ §2 数据流动画（便签 → 状态 → localStorage 三站变形）
- 模块 0 总览 → §10a bars 目录职责导览图（每目录一栏，note 写一句话职责）
- 依赖分层 → §10a bars：运行时强依赖 2 个 vs 可替换抽象层 0 个（数字清点自 package.json，anchor 注明）
- 所有代码讲解 → §1 翻译块

**第 7 步 · 应用型测验**（示例）

> 🧪 你想让 AI 给待办加"收藏星标"，应该让它改哪些文件？
> A. 只改 TodoItem.jsx ❌（不对——星标状态存不下，刷新就丢）
> B. 改 App.jsx 的状态结构 + TodoItem.jsx 的显示 + useLocalStorage 无需改 ✅（正确：状态形状在 App 定义，显示在 Item 改；localStorage 逻辑是通用的，不用动）
> C. 改 index.html 加一个星星图标 ❌（图标不是状态，数据没地方存）

每个选项的 `data-why` 都指向具体文件与代码行。

**第 8 步 · 组装**

此时把 `resources/base.css` 全文原样内联进 `<style>`（design-system.md 仅按需参考理念），产出 `todo-app-course.html`（单文件、双击即开、←/→ 翻页）。

## 示例 2：后端 API 服务 — Express 订单系统

### 用户输入

> code2course ./orders-api 我队友写的这个后端我完全看不懂，每次 AI 改崩了我都不知道怎么描述问题。

### 执行要点差异

**流程选择**（第 2 步）偏向请求生命周期：

1. `POST /api/orders` 创建订单（参数校验 → 落库 → 返回）
2. `GET /api/orders` 列表查询（含分页）
3. JWT 登录鉴权（中间件链）

**代码路径追踪**（第 3 步）示例——流程 1：

```
HTTP 请求进入
  → server.js 的 app.use(express.json())       ← 请求体在这里从字节流变成 JS 对象
  → routes/orders.js 的 POST '/' 路由匹配
  → middleware/auth.js 验证 JWT                ← 保安查身份证
  → controllers/orders.js 的 createOrder()     ← 业务规则在这里
  → models/Order.js (Mongoose) .save()          ← 真正写进 MongoDB
  → res.status(201).json(savedOrder)            ← 原路返回给调用方
```

**可视化选型**（第 6 步）：

- 中间件链 → §2 数据流动画：请求数据每过一站被加工一次（原始字节 → JSON 对象 → 附加 userId → 落库文档）
- `POST /orders` 全链路 → §12 栈塔：`auth中间件`、`controller`、`Model` 逐帧压入调用栈、`res.json` 后逐层弹返回
- 鉴权链各环节的先后与耗时 → §10b timeline：`express.json()` → `auth.js verify()` → `.save()` → `res.json()`（t/dur 来自超时常量与中间件注册顺序，anchor 标注出处）
- 项目分层 → §10a bars 目录职责导览图：routes / controllers / models / middleware 各一栏，note 写职责、anchor 注明清点出处

**测验示例**（第 7 步）——考察调试直觉：

> 🧪 用户反馈"下单偶尔 401"，AI 说改了代码但没说改哪。你会先查哪个文件确认？
> A. `middleware/auth.js` ✅线索：401 全部由这个文件抛出，先看它的验证逻辑和最近的改动
> B. `models/Order.js` ❌模型层问题通常报 500 而不是 401
> C. `routes/orders.js` ❌路由只决定"谁处理请求"，401 是鉴权中间件拒绝的

## 示例 4：触发边界 — 什么时候不该激活

| 用户输入 | 是否激活 | 原因 |
|---|---|---|
| "把这个代码库变成课程" | ✅ | 显式触发短语 |
| "教我理解这个 repo 怎么工作的" | ✅ | 隐式触发三条判据全满足：指向具体代码库 + 讲解式期望 + 范围大于单个函数（激活后第 0 步仍要先问档位） |
| "帮我梳理这个项目的调用链，我想系统搞懂它" | ✅ | 三条判据全满足（系统搞懂 = 讲解式期望）；激活后先问档位，不默认开跑 |
| "帮我写个 README" | ❌ | 产出物不是课程，走普通文档任务 |
| "给我讲讲什么是 REST API" | ❌ | 没有指向具体代码库，是通用概念问答 |
| "这个函数干嘛的？为什么要在这里加锁？" | ❌ | 单点问题（范围 = 单个函数），走普通问答——隐式触发判据③不满足；想系统学再明说 |
| "把这个项目部署上线" | ❌ | 与教学课件无关 |
| "code2course D:\repo 但只要文字版教程，不要 HTML" | ⚠️ 部分激活 | 可复用第 1–5 步分析流程，但跳过第 6–8 步组装，明确告知用户技能的完整产出是交互 HTML |

判据全文见 SKILL.md frontmatter「触发条件」的隐式触发三条（① 具体代码库 ② 讲解式期望 ③ 范围大于单函数）；中间地带先按普通问答澄清范围，不抢跑。

## 示例 6：大型项目 — 多文件拆分输出（执行流程第 9 步）

### 用户输入

> code2course D:\projects\shop-platform 这个全栈电商项目太大了，帮我拆成课程。

### 触发判定

仓库 = React 前端 + Express API + 任务队列 + 部署脚本——**3 个以上独立运行的进程/服务**；且"下单 → 支付回调 → 库存"这一流程族预计需要 15 个以上代码片段 → 满足 workflow.md §9 拆分条件（体积参考线：单册 >350KB 建议评估拆分、>500KB 红线须拆分或向用户说明）。

### 拆分结果

```
course/
├── index.html        # 总目录：封面 + 5 张分册卡片（点击相对路径跳转）
├── 01-overview.html  # 全站目录职责导览图 + 技术栈地图
├── 02-browse.html    # 用户流程族：浏览商品 → 详情 → 加购物车
├── 03-checkout.html  # 用户流程族：下单 → 支付回调 → 库存扣减
├── 04-account.html   # 注册登录 → JWT 鉴权中间件链
└── 05-background.html# 任务队列：订单超时取消、邮件发送
```

拆分自查（对照第 9 步禁止项）：

- ✅ 每册自包含：`resources/base.css` 与 `resources/app.js` 逐册原样内联，把 `03-checkout.html` 单独拷到别的机器仍能打开
- ✅ 流程不劈裂：支付回调与它触发的库存扣减在同一册（02 只讲到"购物车数据如何存"，不碰下单）
- ✅ 册间导航：每册页头有"← 上一册 / 目录 / 下一册 ↓"；本册内 ←/→ 仍翻本册模块
- ✅ 隐喻全局查重：购物车→超市手推车（02 册）、JWT→演唱会手环（04 册）、消息队列→餐厅传菜口（05 册）——跨册无重复
- ✅ 测验与代码同册："下单失败但库存却扣了，先查哪里？"在 03 册，考察的正是该册的支付回调代码

交付方式：整个 `course/` 目录打包为 zip 发给用户，并提醒"解压后双击 index.html 开始"。

## 示例 7：分段生成与拼接（防止整课因输出上限而简略）

### 场景

仓库较大，单文件课程预计 12 个模块、30+ 组件。若第 8 步一次性写出整份 HTML，极易中途截断或被迫压缩成简略。正确做法是按 workflow.md §8.0 **分段生成**。

### 拼接清单（节选）

| 文件 | 段序 | 模块 id | 包含组件 | 代码片段 | 术语/隐喻 | 状态 |
|---|---|---|---|---|---|---|
| course.html | 1 | #m0 封面 | .hero-stage + §10a 目录职责图 + 技术栈标签 | — | — | ✅ |
| course.html | 2 | #m1 入口与调用链 | 探照灯 + 翻译块×2 + 赌注 | src/main.jsx·3-9 … | 挂载点 | ✅ |
| course.html | 3 | #m2 状态管理 | 数据流 + 翻译块×2 + 测验 m2-q1 | src/App.jsx·12-18 … | 便签本(React 状态) | ✅ |
| … | … | … | … | … | … | … |

### 逐段产出（§8.0 第 3 条）

- 段 1 只输出封面 `<section class="module hero" id="m0">…</section>`，写完即回填清单
- 段 2 只输出模块 1，写完回填；若模块 1 组件过多，先"结构层"一段、再"机制层 + 流程层"一段
- ……直到清单每一行都标 ✅
- 最后按段序把各段粘入 course-template.html 的 `.content`，补 `.module-nav`，全局复查后交付

> 关键：每段都是完整可粘入的 `<section>`；接近输出上限时在组件边界收段、下段续写，绝不压缩或删减组件——这是"分段防简略"和"为省字数而砍内容"的本质区别。

## 示例 8：讲解档位 —— 必问选档与随时切档

### 用户输入（未指定档位）

> code2course D:\projects\shop-platform

AI **不能默认、猜测或自动选档**，第 0 步先停下并提问、等待确认：

> 请问用哪个讲解档位？
> ① 快览档 —— 15 分钟建立全局心智模型（粗分段、少组件）
> ② 标准档 —— 吃透主要流程（3–5 个流程族各成模块）
> ③ 精讲档 —— 逐文件逐函数吃透、可动手改（细分段、多测验）

用户回复"③ 精讲档"后，AI 才按 L3 开始生成。

### 用户输入（已含档位词，仍须确认）

> code2course D:\projects\shop-platform，用**快览档**，我只要先看懂大局。

AI 复述确认："确认用快览档（L1），对吗？确认后我将只覆盖 1 个入口 + 2 个最高频流程，全课约 4 屏。" 收到用户确认后再按 L1 规划：每模块 0–1 个翻译块、1 个动画、0–1 个测验，优先单文件、粗分段（1–2 段拼完）。

### 用户中途切档（升档）

> 等等，看完概览我想**切到精讲档**，把"下单 → 支付 → 库存"这条链彻底讲透。

AI 的调整（§0 切档规则第 2 条，不推倒重来）：

- 复用已完成的第 1–4 步分析产物与第 2.5 步四张表，**不重新侦察仓库**；
- **未生成部分**立即按 L3 重新规划：该流程族拆成"订单入口 / 支付回调与幂等 / 库存扣减与补偿"3 个模块，每模块 ≥3 翻译块、≥2 动画/图表、≥2 测验，分段按"结构层/机制层/流程层"细分；
- **已生成的快览段**按 L3 重写补足深度与组件，并向用户一句话说明"前 4 屏已按精讲档回炉重写"；
- 交付前对照 quality-gates.md 复核：全课与最终档位（L3）一致，无"前半快览后半精讲"割裂。

### 用户中途切档（降档，已指明目标档）

> 太细了，切回**标准档**就行。

AI 将未生成部分按 L2 规划；已生成的精讲段按 L2 合并精简（删次要组件、合并分层模块为单模块），同样保证最终全课统一在 L2。
